# Task6A Native Closed Probe Rehearsal Design

The delivered closed consumer has modeled composition coverage but no joint
real PostgreSQL/socket/root-file custody witness. Close this causal verification
gap without changing production source or creating the fixed Setfarm namespace.
Root is the sole writer; two independent agents review read-only. Standing owner
authorization covers this isolated disposable rehearsal, not live grants/accounts.

## Boundary and alternatives

Reuse the existing protected private PG lifecycle, with one explicit additional
`SETFARM_TASK6A_TEST_CLOSED_PROBE_FIXTURE=1` opt-in requiring the base opt-in and
refusing held-PG31 mode before effects. Preserve the old exact policy profile.
The additional profile admits only local database setfarm, role setfarm_runtime,
peer-mapped from _www; all existing rejects remain. Create the limited role and
database only inside the new owned cluster. Never modify live PostgreSQL.

Use the existing isolated `/Library/Application Support/setfarm-task6a-descriptor.XXXXXXXX`
pattern, not `/Setfarm`. Install one root0444 diagnostic JSON file under root0755
ancestry. The genuine generic root-file holder owns five actual FDs; the genuine
generic socket holder checks the private socket. Neither is fixed-source authority.

Bundle the entire unchanged production probe and client. A test-only esbuild
plugin replaces ONLY the probe's exact holder import, importer-bound, with a
test-owned composition of those two genuine generic holders. No source constant,
SQL, tuple or driver result is rewritten. No production seam is added. The private
JSON contains diagnostic transport data, not a protected production descriptor.

Healthy invocation must resolve undefined after two actual fixed queries. A
second invocation with the already allowed task6a_runtime/postgres transport
must make a genuine native connection and reject the real wrong-role/database
tuple. No authentication/setup error may satisfy this negative control.

Observe originals with pass-through fs.openSync/closeSync and Socket.connect:
enroll opens only during holder acquisition; key each occurrence, not FD number.
At genuine native close every FD remains open; explicit holder close follows
that event and closes each once. Probe settlement follows the native event and
all FD closes. Restore instrumentation in finally. This establishes actual event
ordering, not a driver graph freeze. A third control defers only the captured
real socket's original `_destroy`, waits an actual25ms timer turn, and requires
the probe to remain pending with all five FDs live/zero closes. Release invokes
that same genuine original, then joins the probe; finally also releases/joins
on assertion failure. This proves withholding at this native boundary only.

Reuse existing exact PG cleanup; retain on uncertain child/postmaster completion.
The additional descriptor leaf cleanup validates captured dev/ino, root ownership,
mode, exact sole regular member and no symlink/hardlink, then removes only that
member and empty owned leaf. Never recursively remove a broad namespace.

Alternatives rejected: private/tmp root-file ancestry exemptions, fake rows/role
constants, installing fixed authority, or exporting production callbacks. Separate
native-image copying is unnecessary and disabled; Homebrew executables are not
authenticated deployment/native-image authority.

## Delivery limits

First RED is the new exact healthy policy profile rejected by the old validator,
not missing imports or an unavailable tool. Run base policy regression and default
skip before privileged admission. Genuine native GREEN, complete original child
close, source pins, actual raw artifacts, strict types and independent review
precede same-branch delivery. Maintain sampled8GiB free floor. This rehearsal
does not clear fixed deployment, grants/catalog, owner admission, stock clean-main
build, OpenClaw rollback metadata, or live3333 cutover gates.
