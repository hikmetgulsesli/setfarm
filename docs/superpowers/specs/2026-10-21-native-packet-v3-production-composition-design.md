# Native PacketV3 production composition design

Status: Root-adopted causal root-fix design, 2026-10-21. Implementation and runtime qualification pending.

The authorized working-Setfarm objective requires a producer and consumer that share the same packet family. The first real current full8 run published PacketV3, completed planning/design/story/setup steps, then repeatedly refused its first implementation claim because production injected the PacketV1/V2-only reader. This is a platform root cause, not a generated project defect. A reader-only change would expose additional unsupported production contracts.

Evidence: retained job d756f305-338b-4613-a055-36773303628c and run914f439c-198f-4bfc-8444-c94bee803fcf, Source161297ffca6adf2851918a93d492e1c9a77ce59d; exact diagnostic V3_NORMAL_PRECLAIM_PACKET_UNAVAILABLE. The owned run was subsequently cancelled. The original evaluator exited1 during settlement; its active reservation is a separate recovery concern. No passing case or full8 qualification is claimed.

## Root decisions and scope

Use the explicit native PacketV3 family: PacketV3/ProductSpecV2/StoryPlanV2/SourceMapV1 and the existing strict `slice-compiler-v2-legacy` native semantics. The current unsuffixed PacketV4 compiler remains a separate unactivated family. Never downgrade a packet or widen legacy readers.

Reuse the V2 immutable preparation authority ledger and its transaction-taking publication/binding APIs. Preserve the V1 readiness projection only as a distinct exact eligibility/CAS fence; V1 and V2 hashes are never interchangeable. Prove the bridge against real isolated constraints. Any actual additional persistence need requires an additive design amendment before migration work.

New native wire schemas are `setfarm.native-v3-evidence-plan.v2`, `setfarm.native-v3-implementation-handoff.v2`, and `setfarm.native-v3-implementation-context.v2`. These names are new contracts, not assertions that existing V1 contracts support PacketV3. Bind native family, producer, packet/report/slice/plan/source/claim/attempt/generation identities, full predicates and immutable authority. Preserve the existing256KiB serialized context boundary.

One dispatch authority transaction must publish the exact readiness consumption, native authority, claim/runtime/attempt ownership and indexed refs atomically. Dispatch only after commit. A later completion transaction reloads the durable native chain independently and rejoins current fences; no transaction spans model execution.

The first test phase must exercise real public claimStep with a real indexed native packet, a pending admitted story, valid predecessors, clean source and a real isolated PostgreSQL fixture. It must reach the observed reader mismatch, not a bootstrap error. Only after Root captures genuine RED may production code change.

The first implementation slice ends at platform-evidence-backed fenced initial story completion. It does not qualify final workflow/full8. Native final-source accepted candidates, downstream evidence/review/deploy, retry/recovery and evidence-only attempts remain required wherever the workflow needs them; each must use its exact native contract or refuse before effects. Do not ship partial production activation or claim workflow GO while a required path remains unsupported.

No service, live database, role, credential, guard, old run or private reservation change is authorized by this design document alone. Existing user authority and current evidence gates govern effects. All Source/test changes stay on the sole writer branch; Root owns execution and delivery.

## Recommendation and alternatives

Adopt **an explicit PacketV3 normal-initial-attempt composition**, keeping packet-family dispatch separate from run protocol. Complete native preparation authority, SliceV2 assembly, EvidencePlanV2, HandoffV2, ContextV2 and fresh durable reload together before making a native claim dispatchable. Integrate the actual evidence runner and completion consumer in the same vertical slice. Preserve the existing PacketV1/V2 path and its rejection boundaries.

## Proposed semantic contracts

Names in this section are NEW and require typed schemas, independent validation and tests. Exact wire schema/type strings must be frozen in the adopted design before production code; they must not collide with canonical PacketV4 contracts or reinterpret an existing V1 payload.

1. **Native preparation result.** Discriminate by authenticated `packet.schema === setfarm.product-build-packet.v3` plus sealed ReportV3/native child closure, not by prose, presence of a context key, or protocol alone. A ready native result contains a canonical `V3PreparationClaimAuthorityV2`, the exact eligibility-state identity used to mint it, immutable packet/report refs, exact base SHA/tree, and bounded assembly inputs. A ready V1 result stays a separate variant. Never expose a native AuthorityV1 as sufficient dispatch authority.

2. **Native EvidencePlanV2.** Compile directly from the strict PacketV3 SliceV2 family and exact slice-envelope hash. Bind packet, report/source-map lineage, story, slice and producer identities. Preserve every required product predicate, observable hash, assertion value/phase, route/control/source binding, action-input transport, prerequisite, command and runtime capability. Keep plan payload hash distinct from semantic-envelope hash. Derive selectors and argv solely from sealed authority. No physical-control-count proxy, fake selectors, dropped predicates, prose reparse or unsupported-capability pass. A required unsupported adapter blocks/inconclusive according to existing policy. The existing V1 flow executor may share genuinely common leaf logic only after explicit validated native semantics, never through `as SliceV1` or field-loss projection.

3. **Native HandoffV2.** Carry exact run/step/story DB identity, claim ID, attempt ID/generation, packet/report/preparation-authority hash, source SHA/tree, producer, native slice+ref+envelope hash, native plan+ref+payload/envelope hashes, branch/workdir and execution role/profile. Recompute all cross-hashes and exact sets on parse. Native packet discriminator must also select the correct native SliceV2 family despite the shared numeric version/type. Keep capability/fence token in the private ClaimEnvelope, as HandoffV1 already does; do not expose it in model context. The handoff is not authorization merely because a caller constructed a typed object.

4. **Native ContextV2.** Produce a canonical bounded schema from a validated HandoffV2. Exact allowed paths come from owned and shared-writable native grants, excluding shared-readonly and undeclared paths. Include original observable and source-map constraints plus the strict output contract. No stringifying arbitrary objects, truncating contract fields or reparsing legacy compatibility prose. Preserve the current 256 KiB context cap unless a separately reviewed capacity design is actually needed. Check final serialized capacity before claim transaction commit/dispatch; overflow rolls back reservation. A 4 MiB artifact cap is not permission to expand context silently.

5. **Native durable reload / output compilation.** Fresh process loads the actual claim+attempt+V2 authority/claim/attempt bindings, exact native packet/report/children, indexed native slice envelope and indexed plan envelope. Verify CAS bytes/producer and independently reverify the slice against its authenticated inputs; derive/compare the exact plan again. Do not capture “sourceBefore” from the now-modified worktree or regenerate authority from agent output. At completion the original snapshot remains the before fence; candidate source is separately captured/committed by existing platform gates. Compile the untrusted proposal against the reloaded context. Preserve existing proposal canonicalization and rejection of caller-provided compiler evidence. `ready_for_evidence` remains a request for platform verification, never a PASS claim.

## Claim publication and completion transactions

“One authority transaction” does not mean holding a database transaction across model execution. It means one commit for the complete dispatch authority, then a later independently fenced completion transaction using that durable chain.

### Preparation and the one claim commit

- Preclaim may read/validate sealed CAS and prepare bounded pure slice/plan bytes. It can record diagnostic preparation blocks using existing policy. It must not publish a claim owner, runtime owner, dispatchable handoff or attempt as partial success.
- Retain the current recovery/preparation advisory-lock ordering before run-row locks (`claim-runtime-publication.ts:1915`); incorporate attempt lock ordering consistently with `attempt-repository.ts:705`. Test concurrency against termination, recovery and sibling claims; do not insert a reverse lock order. Use one caller-owned transaction-taking composition seam. Existing `publishLoopClaimRuntime` itself opens `sql.begin`, so returning from it and then calling reserve is not that seam.
- Under those locks, validate active pinned run protocol/packet, run/step/story eligibility/order/dependencies, exact English-admission proof, runtime intent/caller role, current source/base fence, state version and absence of conflicting owners/blocks. Rejoin full native dependency terminal attempts: attempt ID/generation/class/disposition, slice/output hash, sourceAfter SHA/tree and exact file signatures, with same packet and projected IDs. Recompute AuthorityV2 rather than trusting a caller-supplied “ready” assertion.
- **Keep eligibility projection and native authority distinct.** Existing preparation-story state stores a V1 eligibility authority hash. Minimal proposed bridge: retain that V1 state/fingerprint as a checked readiness/claim-CAS projection, bind the native V2 authority to that exact stateVersion and full revalidated rows, and publish it in the existing V2 immutable ledger. Do not compare V1 and V2 hashes as equal, stuff a V2 payload into V1 columns, or treat V1 alone as native authority. The native branch must separately consume readiness by exact CAS and bind AuthorityV2→claim→attempt. If concrete DB constraints prevent this bridge, stop and propose an additive versioned readiness migration; do not weaken old constraints. The bridge's replay and rearm semantics are required RED/GREEN coverage, not an assumed existing API.
- Atomically create/consume readiness, story/step claim projection, real claim birth and internal-production owner reservation; reserve the real generation/fence via `reserveAttemptInTransaction`; publish/bind AuthorityV2 with the existing transaction-taking APIs; join native slice/plan refs and runtime-session/attempt association. All are one transaction and affect exactly the intended rows.
- CAS filesystem bytes can be prepared before the transaction under existing publication/quota/trusted hybrid-writer rules. Committed run refs/ownership cannot appear separately. `artifact-index.ts:2534` currently opens its own transaction for `addRunArtifactRef`; the native coordinator needs a transaction-taking ref method preserving conflict/identity/immutability checks. Do not call the standalone helper and claim atomicity. An immutable unreferenced CAS artifact after rollback is not a live claim; retain existing orphan/quota policy, no new cleanup.
- Construct and fully validate/cap the actual HandoffV2/ContextV2 with the real reserved identity before commit. Return/disclose/dispatch only after commit. Worktree preparation, source validation and provisioning failures use existing fenced ownership/failure paths; no dispatch until the exact worktree is verified. Do not move Git/network/provisioning work into a long-lived transaction merely to force a claim of atomicity. A pre-dispatch failure must retain a truthful terminal attempt/claim or a complete rollback according to the actual publication boundary.
- Replay with the same runtime intent returns exactly the same committed authority/claim/attempt tuple; conflicting intent/authority is rejected. Concurrent claims create one owner, never a second generation as an accidental retry. No changed packet default converts an existing run.

### Later completion commit and effects

`v3-implementation-completion.ts:27–77` currently asserts claim authority and reloads the V1 attempt before canonical output compilation. `runtime-completion.ts:1552,1604,1617` invokes that compilation before the request transaction. Current code **also** locks runtime owner, attempt and claim inside the transaction (`:1640–1780`), checks generation/fence/runtime association and lease; preserve those protections.

For the native branch, carry only an authenticated immutable compilation identity into that transaction and rejoin it under the current locks to AuthorityV2→claim→attempt, packet/report/slice/plan hashes, producer and source-before fence. Recheck current lease, termination, generation/fence, runtime session, story/step/claim ownership and relevant exact row counts at request publication and actual effect acceptance. Do not rely solely on the earlier read. The token/owner checks are existing authority, not model-supplied fields.

Pre-drain CLI parsing, the runtime completion proposal compiler, post-drain completion effects and spawner reload all use the same versioned loader/context. Preserve original worker settlement and proven runtime drain requirements; a V2 context is not EOF or no-owner evidence. Canonical output or evidence may be published only through existing owner/fence paths. Stale output changes no current owner/state and remains diagnostic. Exact request replay remains idempotent after terminalization.

Native evidence runs the declared commands/adapter through the real platform. Persist full canonical bundle identities and exact predicate coverage. Numeric worker success, story completion, command success and evidence PASS remain different facts. Native failure/inconclusive generates a typed bounded finding from the same exact native ownership/snapshot and cannot inherit a historical pass.

Root owns all execution and isolated test resource admission. The following describes future tests, not results. Public test fixtures remain disposable and isolated; they cannot waive production guards or mutate the current cancelled run.

Actual completion request and effects rejoin the exact live claim/runtime/attempt/generation/fence, V2 authority, packet/report/slice/plan/source identities under locks, commit once, and advance only the permitted story/step.
