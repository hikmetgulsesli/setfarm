# Held positive-worktree physical catalog V2

Status: diagnostic-only continuation of the approved positive physical-plus-PostgreSQL ownership direction. The merged pure partition (#146) is not a host observer or cutover authority.

## Current evidence and safety boundary

The historical V1 observer requires several absent fixed bases and treats all managed children as Git non-primary worktrees/owners. The host instead has retained linked development worktrees, independent deployment primary clones, two non-Git workspace data directories containing current-entry records, and a non-Git VectorGate project child containing supervisor artifacts. The VectorGate parent also lists prunable Git worktrees with absent paths. Names, record shapes, age and `git -C child rev-parse` (which can climb to a parent repository) do not authenticate any of these unknown directories. Keep every directory visible. Do not delete, move, prune, repair, or relabel it as retained without positive provenance.

## This slice

Add an import-inert, read-only V2 held physical catalog with a fixed code-owned host-scope wrapper and a separately labeled fixture-scope diagnostic core. The owner home, code-owned workspace, projects root and OpenClaw workflow root are mandatory anchors: if any is absent or unsafe, refuse rather than synthesize an empty census. The scope includes existing/absent workspace `.worktrees`, Setfarm and Mission Control `.worktrees`, deployment clones, OpenClaw scratch/workflow story-worktree bases, and every project `.worktrees` base. Only optional leaf bases beneath authenticated present parents may be recorded absent, with their held parent; an absent parent that prevents enumerating descendants refuses. Every present managed-base child is recorded, including unresolved non-Git directories; non-directory/symlink children in a managed base refuse. Ordinary files in a discovery parent (for example macOS `.DS_Store` in the projects root) are listed separately as incidental files, not silently dropped or promoted into worktrees. Symlinks refuse everywhere. Bound the parent/base/child counts to accommodate the observed 280 project directories.

Pin all ancestors, bases, and children with `O_DIRECTORY|O_NOFOLLOW`; compare `lstat` and `fstat` device, inode, birth, mode and UID everywhere, plus ctime and mtime within the owner home, before, after, around every path-based external command, and across an awaited read-only callback. Shared ancestors above the home may change for unrelated users; their identity remains pinned while mutation metadata is scoped to the owner-controlled subtree. Pin each direct `.git` marker no-follow and authenticate its Git directory/common-dir reference before treating command output as Git identity. A rename-away/replace/restore during a command must be detected through held parent/child change metadata; if command-to-inode binding is uncertain, refuse. Close exactly once; failed close poisons later acquisitions. An unstable/missing/symlinked path refuses. No cleanup or path mutation is permitted. Capture open-file/cwd reference PIDs with a bounded `lsof +D` scan from the held workspace cwd; strip and report the observer's own PID because its held directory descriptors are self-references. When Darwin `lsof` reports status 1 with only that observer reference, corroborate with an observer-excluded scan that must return status 1 and empty output; any other ambiguous output refuses. `lsof +D` does not prove absence of argv-only, descendant or orphan processes; a future authority stage must compose the global ps/cwd family and listener census independently. Status `complete` means this diagnostic catalog's own checks completed; it never means zero-owner admission.

Authenticate Git topology with a direct `.git` marker, exact `git rev-parse --show-toplevel === candidate`, authenticated primary/common-dir linkage, and exact membership in a complete non-prunable `git worktree list --porcelain -z`. Disable repository-local `core.fsmonitor` for Git status so observation cannot execute an untrusted helper. An allowed Setfarm/Mission Control remote origin corroborates retained-zone topology but cannot prove source/build provenance. A code-zone primary clone may have `candidate === primary`; a linked worktree must authenticate its membership in the primary list. Runtime-zone entries must resolve to the containing generated project primary. A present managed base beneath a non-Git project parent still enumerates children and carries a `non-git-parent` blocker. Every Git-listed worktree outside the enumerated managed scope is an unresolved blocker unless it is the expected primary anchor; absent/prunable listed paths always block. Unknown/non-Git entries remain visible as `unresolved`, not `retained-artifact`; any unresolved entry makes the catalog non-qualifying. `primary-git` and `linked-git` are topology labels only; every entry explicitly reports `sourceBuildProvenance: "unverified"`. A future provenance contract must authenticate source/build identity before any retained classification or ownership claim, including for an origin-matching deployment clone.

The catalog records all observed entries, absent bases, process references, and blockers. This slice never produces Stage-1 physical entries, even when `status` is `complete`; source/build provenance and PostgreSQL linkage remain unverified. It never reads PostgreSQL, calls the V2 partition, changes historical V1 code, or grants complete-zero/cold/cutover authority. The callback is for future read-only DB bracketing, not a caller-supplied zero-owner assertion.
