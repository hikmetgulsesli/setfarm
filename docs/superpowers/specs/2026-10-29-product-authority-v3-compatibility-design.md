## Alternatives and decision

1. **Explicit PBA v3 with exact native packet authority (recommended).** Add a discriminated native subtype and retain the existing legacy subtype; opt in at every request boundary. Slightly larger than a reader rename, but preserves wire semantics, graphless authority and typed source-map provenance.
2. Widen PBA v1/v2 and swap reader methods. Reject: existing consumers require ProductSpecV1, graph V1 bindings, StoryPlanV1 and packet v1/v2. This changes established meaning and encourages unsafe casts or invented graph bindings.
3. Read a separate native endpoint only after a v2 mismatch. Reject: couples authority selection to an error and doubles request/race/error behavior. A single explicit version request is smaller and more auditable.

## Wire contract and negotiation

SF retains GET /api/runs/:id/product-build-authority. Missing schema means v2; schema=v1 and schema=v2 retain the exact existing successful bodies, reader family and error-code mapping. schema=v3 selects a new schema. Reject unsupported/empty or repeated schema values with HTTP400 and PRODUCT_BUILD_AUTHORITY_SCHEMA_UNSUPPORTED, without constructing a reader or touching storage. This is an intentional fail-closed change only for invalid version requests; no valid legacy request changes meaning. Leave unrelated query handling unchanged.

MC retains its endpoint. Missing schema means v2, accepted explicit values are v1/v2/v3, and the browser fetcher adds ?schema=v3. MC forwards the chosen version explicitly to SF. Thus old API clients still receive old default meaning. Hook polling and run identity behavior remain unchanged.

Outer v3 is a strict object with exactly schema, runId, disposition, packetAuthority, refusal, authorityHash. schema is setfarm.product-build-authority.v3. disposition is sealed_packet or refused_before_packet, with the same null/exclusive rules as v2. For sealed_packet, packetAuthority is a schema-discriminated union of unchanged ProductBuildAuthorityV1 and new ProductBuildPacketAuthorityV3. Refusal is the existing exact ProductBuildRefusalV2, with all v2 refinements retained. runId equals the nested packet authority's runId. authorityHash is hashCanonicalJson of the full outer object excluding only authorityHash.

Native ProductBuildPacketAuthorityV3 schema is setfarm.product-build-packet-authority.v3. Fields are the exact SealedRuntimePacketV3 fields plus schema and authorityHash: runId, packetHash, producer, productSpec, designGraph, buildTopology, storyPlan, designSourceClosure, implementationSourceMap, optional designSources, packet, compilationReport, refs. No flattening or renaming native packet payload fields. Native authorityHash binds this entire identity. refs has productSpec, designGraph, buildTopology, storyPlan, designSourceClosure, implementationSourceMap, packet, compilationReport; only designGraph may be null. Null is mandatory for graphless native packets, not an omitted value or empty fabricated graph.

Use existing SF Zod schemas for ProductSpecV2, DesignInteractionGraphV2.nullable(), BuildTopologyV1, StoryPlanV2, DesignSourceClosureV2, ImplementationSourceMapV1, ProductBuildPacketV3, sealed ProductCompilationReportV3, and exact native design-source types. designSources has generationTargets v2, directResponseEvidence v2, renderedSemantics v2, candidateSelection v2, responseBindings v3. Reject unknown/mixed versions and extra outer/ref/source-set keys.

## Integrity and authority boundaries

Only the exact reader can obtain native runtime authority. It retains actual guarded store/index reads, compiler-release pinning, canonical run refs, typed child reads, producer comparisons, payload and envelope hashes, deterministic StoryPlanV2 reproduction, report equality, source-map and runtime contract comparisons. Do not change runtime-artifact-reader.ts, its legacy contract or storage mode defaults for this fix.

The native response schema additionally checks its self-contained wire relationships: packetHash=refs.packet; all six versioned packet child hash fields equal the corresponding refs; report is sealed with equal compiler, packet hash and all six report child refs; producer.codeSha equals packet/compiler codeSha. Reconstruct and hash the eight top-level semantic envelopes using the exact common packet producer (graph omitted for kind=none), compare to refs. All top-level producers are already required equal by the reader. Verify native source-map payload hashes against product/spec/graph/topology/story/closure payloads, graph/story payload relationships, and runtime contract pairing/topology equality. All design-kind witnesses agree with productSpec.delivery.designRequired.

For Stitch require graph, all five typed sources, exact graph closure envelope/payload refs, closure child payload hashes, and exact source-map screen/target/response cardinality and hashes. For none require graph=null, refs.designGraph=null, packet/report graph hash=null, closure.kind=none, no designSources, implementationSourceMap.designSourceKind=none and empty screens with null graph/converter/index references. Preserve acceptedAttempt/artifactManifest/projectionReceipt references from DesignSourceClosureV2 as references only; they do not prove deployment, accepted final product candidate, build success or runtime execution.

**Nested producers are distinct.** readClosureChildV3 validates nested index producer against its stored envelope, not against the packet producer. The current read result carries nested payloads and typed closure refs, not nested producer envelopes. Neither SF wire schema nor MC may reconstruct these nested envelope hashes using the parent producer. Validate nested payload hashes/types/references available in the wire and preserve exact closure envelope refs. The guarded exact reader remains responsible for nested envelope/index provenance. No additional runtime reads or fabricated producer fields are needed.

MC is a validation/presentation boundary, not a second artifact authority. Its dedicated native parser checks exact outer identity/discriminants, typed version labels, every field rendered, canonical outer/native hashes, top-level envelope/hash bindings and the self-contained relationship rules above. Use the existing pure server/services/setfarm-canonical-json-v1.ts hash function directly and existing legacy/refusal validation through callbacks; never import the operational-snapshot hash re-export. Extract the current service parser/client into a pure core while leaving production configuration defaults and singleton creation in the existing facade. Avoid importing SF checkout code or adding a dependency. Retain raw typed native collections so no technical detail is discarded. Browser parsing validates discriminants and renderable native structures and refuses malformed/missing required structures; server-side hash validation remains authoritative, just as today. Do not label browser checks as CAS validation.

## Missing, terminal, refusal and old-backend behavior

V3 attempts readExactSealedPacket and audits with auditExactTerminalPacket only for RUNTIME_PACKET_NOT_ACTIVE. Current active statuses running/resuming and terminal completed/done/failed/cancelled/canceled/error/blocked remain owned by the reader. An unknown status must not be treated as terminal. No recovery/restart follows from inspection.

Only RUNTIME_PACKET_NOT_SEALED may try readVerifiedDesignCandidateRefusal, exactly as v2. A canonical failed terminal termination, exact immutable ref/index/CAS envelope and failure identity are still required. Missing refusal rethrows the original not-sealed error. Type/hash/release/closure errors never become refusal or successful authority. Missing run ->404; existing not-v3/not-active/not-terminal/not-sealed ->409; reader integrity/ref errors and refusal integrity errors ->503. Keep error codes literal. V3 error bodies use setfarm.product-build-authority-error.v3. Unexpected failures remain failures, never authority.

An older SF may ignore schema=v3 and return valid v1/v2. MC accepts it only through the unchanged legacy validators and displays the actual version. An older MC may likewise return legacy to the new browser. No response is relabeled as v3. Old backend 503 RUNTIME_ARTIFACT_TYPE_MISMATCH stays upstream_error/http_error with that code. 404/409, network/timeout, invalid JSON, malformed known-schema payload, and unknown schema retain their existing classification. Unknown backend schema stays unsupported_schema; a v1-shaped body labeled v3 is invalid_payload. No retry/downgrade loop.

## UI design

ProductBuildAuthority remains in its existing RunDetail location; preserve all technical tabs elsewhere. Split native rendering into NativeProductBuildAuthority.tsx and keep the existing legacy rendering path. Common wrapper/refusal display can be shared without flattening native semantics. Native displays packet v3, story count, compiler/producer, authority/ref hashes, source-map authority and exact source provenance. Graph controls are physical-control identity/action/slot/surface records, not old graph.bindings; native has graph.actions and graph.observables. Render those exact relationships plus element/source hashes. Stitch response bindings show targetHash and the existing screen/HTML/PNG/DOM/observation references. Source-map screens show target, response, path/pathRef, contentHash, owner/story, and mapped control/action-input/observable identities. Keep collections bounded using the existing 200-item display limit with explicit omitted counts.

Graphless native display says "No design graph required by this sealed packet." It still displays product/story/topology/source-map authority; null graph refs show "Not required". Do not count a missing required graph as zero or a parser failure as empty data. A sealed compiler packet means only sealed compiler authority. Do not add passed/deployed/accepted-final labels. Existing cancelled/failed run visibility and status remain untouched.
