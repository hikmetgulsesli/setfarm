# Pre32 physical inventory coverage V1 design

## Boundary

The held V7 physical/database pair is a cold-zero pre32 diagnostic. It rejects nonzero active run, claim, attempt and session counts; therefore it cannot produce a positive execution owner or a runtime binding candidate. Development/deployment worktrees must remain physically visible, but their mere presence must not be silently relabeled an owner or a proved nonowner. The existing V3 residual-absence annotation preserves all original V7 blockers and distinguishes only bounded absence; it does not partition all *present* catalog entries.

Add one distinct diagnostic-only coverage projection over a directly produced V3 annotation. Partition every held physical catalog entry exactly once, in catalog order, into `retainedGitTopologyRoots` and `unresolvedPresentRoots`. A retained-zone linked/primary Git entry qualifies for the first list only when it has a non-null Git primary, no referencing PID, and no blocker at the same root. This list means topology only: dirty worktrees remain visible and source/build provenance remains `unverified`. Every runtime-zone entry, unresolved/non-Git entry, PID-bearing entry, or same-root blocked entry stays unresolved. Preserve the entire original V3 annotation by object identity, including the original V7 blocker array, absent bases and witness; do not subtract blockers or infer a continuous zero-owner lease.

The projection validates the exact V3/V7 schema and cold-zero database counts, nested hashes, frozen members, strict root order and complete partition. It independently checks each present entry's positive decimal physical identity, canonical Git primary, Boolean Git dirty/null unresolved dirty, and root-to-zone path geometry. Retained Git primaries must additionally match the catalog producer's allowed fixed Setfarm/Mission Control or preserved `.worktrees`/`deployments` primary families under the same home. Independent review found that a self-hashed runtime root mislabeled `retained-zone`, or a retained root crossed to an unrelated Git primary, could otherwise be laundered into retained topology; bootstrap repeats both checks independently of the compiled projection. It emits literal `authority:diagnostic-only`, `physicalIdentityProvenance:unverified`, `temporalScope:v7-held-two-pass` and one canonical `coverageHash`. It must never emit owner, nonowner, zero-owner, eligible, ready or cutover admission fields. A separately authenticated bootstrap verb may load the zero-input code-owned observer, validate the nested V3 chain and new partition, then return the unchanged source/build attestation plus this distinct output. It performs no new DB query or host effect beyond the existing V3/V7 read-only observation.

Actual positive owner evidence belongs to the separate non-pre32 held-binding candidate path plus a producer-authenticated execution receipt and continuous DB/OS writer exclusion. This projection grants none of those capabilities; it does not change frozen V1/V7 semantics, migration 32/33, Task6A, service selection or retained worktrees.
